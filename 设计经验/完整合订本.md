## 如何使用这套资料

这套资料供制作教学内容、复习工具和交互练习的人使用。它整理了 CDT505 工作台从资料索引、AON 作图样板到多个专题和线上发布的设计经验，重点记录反复返工的原因、可执行的准则和正反例。

读者面对一页材料，应当能够知道正在解决什么问题，理解新术语，看到推理过程，并用当前给出的条件完成一次尝试。编写者负责把这些联系交代清楚。

### 十条基本判断

1. 先交代谁在做什么，以及为什么需要当前概念。不能用一句医院名称代替完整情景。
2. 正式英文术语、缩写和中文含义先于计算与提问出现。解释新概念时，不再引入一串未解释的术语。
3. 同一活动、对象和案例条件保持一致。切换例子时说明新的工作、金额、工期或假设。
4. 每次推导都让读者看见取数、关系转换、计算和结果含义。只有公式与计算器总数，还缺少教学过程。
5. 题目旁边能查到当前条件。完整名称、表格和单位不能只留在上一页。
6. 简单题可以检验基础辨析；错误选项也要对应真实误解，不能靠荒谬行为或语气让人猜中。
7. 图表依据领域含义判断对错。AON 检查依赖，AOA 接受等价编号，矩阵保留课程规定的轴向和类型名称。
8. 先看解法再填写，与独立答对分别记录。题目或上游条件改变后，撤销受影响的核对结果。
9. 学习、练习、速查和案例册共用事实，分别服务不同任务。增加内容之前，先检查能否补进原有解释并删除重复。
10. 数值正确、按钮可用、页面增多，都不能证明材料读得懂。阅读审阅、功能验证和用户实际反馈分别记录。

这些判断在后文展开为具体规则。它们不是需要额外复制到每一页的十条提示。

### 这套资料怎样区分事实与建议

“实际反馈”指用户已经明确说过的问题或要求；“实际返工”指本项目的内容、实现或审查记录中能找到的变化；“建议示例”用于说明可以怎样写，不冒充已经做过的用户试验。

5.1 是用户指定的比较样板。可借鉴的是同一张活动表逐步支持关系、作图、时间与时差的过程。用户没有因此认可后续每一个专题，也没有授权把功能测试结果写成满意度结论。

截至 2026-11-01，工作台已制作主题 1 至 8，并发布到 [cdt505](https://bicheng.github.io/cdt505/)。本资料包包含这次制作中的经验，也包含为后续工作补写的检查方法。检查方法是否执行，要看对应产物的审阅记录。

### 规则发生冲突时

用户给出的具体表达和使用需求，优先于通用写作模板。例如，本项目需要在操作旁保留速查表，不能照搬“教程中不放参考资料”的建议，让读者反复跳转。

专业事实回到课程材料和经过核对的计算。语言润色不能改变公式的适用条件、时间单位、矩阵方向或评分边界。遇到疑似笔误，应记录差异并核对，不能为了与原文外形一致而重复错误。

自然中文不等于每句话都口语化，也不要求每个句子都有“人”作主语。“工期为 3 天”可以直接写。需要交代行动者时，才写清设计师、工人或项目经理做了什么。

### 文件维护

分章 Markdown 是内容来源。网页版、合订本和压缩包由这些章节生成，修改时只编辑分章文件，再重新生成产物。原有《教学设计与制作准则》同步生成合订本，继续保留原文件入口。网页中的搜索、打印和目录只负责阅读，不再维护另一份规则。

新增经验应补进对应章节；如果它与已有规则相同，就扩充原来的例子和适用条件。不要每次返工都在末尾叠加一份“最新补充准则”。


## 需求与课程编排

最初的任务是建立复习索引，后续要求已经变成面向初学者的教学与练习工具。如果仍按“把材料分好类、提供跳转链接”制作，即使页面数量不断增加，也无法让读者完成学习。开始编排之前，要重新写清当前产品承担什么任务。

### D01　把需求写成读者能完成的动作

“做得丰富”“说明清楚”“比样板好”都表达了方向，编写时还需要具体对象和结果。例如，AON 专题的目标可以写成：读者根据活动信息表识别直接紧前活动，画出依赖关系，在关系正确后计算开始与完成时间，并解释一次延迟影响哪些工作。

这样的目标可以决定需要哪些概念、例子和交互，也能暴露缺失部分。只写“理解 AON、Slack、PERT”，无法说明读者最终要做什么。

| 需求表达 | 设计时应补齐的内容 |
|---|---|
| 全课都要覆盖 | 知识点、课程位置、先修概念、所在专题及对应练习 |
| 所有题型都要有 | 哪个知识点适合辨析、计算、作图、查错或解释，不能强行给每个术语套全部题型 |
| 新手也能用 | 第一处陌生词出现的位置、进入后的第一步、作答时需要的条件 |
| 可以 DIY | 可编辑哪些对象、哪些输入合法、修改后哪些结果需要重新计算 |
| 比 5.1 更好 | 是否延续条件、展开推理、保留当前表格、提供变化后的独立判断 |

学习目标可以保存在设计稿、课程地图和专题介绍中。正文不需要反复命令读者“这一页要学会”“确认你理解了”。

### D02　先建立知识关系，再划分页面

知识点并列，不代表它们可以任意调换顺序。把计算中用到的每个概念写出来，再检查读者第一次需要它时是否已经见过。

投资评价的合适次序是：读现金流表，计算累计现金流，理解普通回收期；随后认识现值与贴现率，计算 NPV 和贴现回收期；最后用 NPV 等于零解释 IRR。若先讲贴现回收期，读者同时需要猜“回收”与“贴现”的意思。

WBS 的次序也由概念关系决定。读者先知道要求与范围边界，再看工作如何分解，认识工作包与词典，最后理解范围基线。把“范围基线”放在组成部分之前，会迫使正文用另外几个陌生词解释它。

一个直接的检查办法是遮住后面的页面，只读当前页。标记所有需要靠后文补定义的词。涉及当前理解或作答的内容应当前移，或在本页用一句话解释。

### D03　三个层级分别回答不同问题

| 层级 | 读者的问题 | 展示内容 |
|---|---|---|
| 知识主题 | 项目管理有哪些方面？ | 主题名称、相互关系、范围与学习入口 |
| 专题 | 当前要解决哪个完整问题？ | 问题背景、主要术语、阅读顺序和对应课程位置 |
| 学习、练习、速查 | 我现在要理解、尝试还是查一个条件？ | 各自所需的正文、题目、表格、工具或公式 |

首页需要建立方向感，不应默认展示制作日志、文件列表和完成数字。课程位置可以帮助读者核对范围，但正文必须承载理解所需内容，不能只留下“见 Lecture X”。

反例是“九宫格 AON / Slack”：标题先给陌生缩写和节点外形，读者不知道用途。正例是“项目进度计划：从活动表到关键路径”，随后介绍 Activity-on-Node、活动节点图和 Slack／Float 的含义。正式术语仍然保留，标题先说明读者将处理什么问题。

### D04　专题边界以完整问题为准

如果两个小专题使用同一组对象，后一部分必须立即接着前一部分才能理解，可以合并。例如需求、范围与 WBS 共同说明“需要完成什么以及如何分解”；风险识别、评估、应对与复查共同说明“怎样处理可能影响项目的事件”。

如果几种内容的判断条件明显不同，应当保留区分。例如普通回收期、NPV 与 IRR 可以属于同一专题，但不应压成一个定义框。它们分别回答收回投入要多久、按要求回报折算后增加多少价值、哪一个回报率使 NPV 为零。

判断是否拆页，看新页面有没有独立的问题、所需条件和结果。页数少不等于简洁，页数多也不等于完整。

### D05　用一条连续解释回答 what、why、how

以下是可用于专题开头的建议写法：

> 医院接待区准备开放。电脑和取号设备要安装好，指路牌也要做好，最后还要一起检查。设计师必须先拿到要求才能画图，工人要等图样完成才能制作指路牌。项目经理需要知道这些工作怎样衔接，哪些可以同时进行，以及最早什么时候能够开放。Project Scheduling（项目进度计划）就是把活动、先后条件和工期整理成可执行的时间安排。

这段话交代了对象和任务，说明计划的用途，也引出了活动、关系和时间。后面再逐项定义，读者知道这些词为什么出现。

反例是分别写三张卡：“What：项目排程。Why：优化资源。How：建立网络。”看似满足了三个栏目，实际没有解释工作之间的联系。“优化资源”还把尚未进入的资源约束提前混进了逻辑排程。

### D06　5.1 的可迁移部分

| 5.1 中的做法 | 其他专题怎样借鉴 |
|---|---|
| 先读活动表，再画关系图 | 投资评价先读现金流表，再写累计或贴现计算 |
| 图正确后才填写时间 | 成本先核对数量与权重，再计算规模、工作量和金额 |
| 正推与逆推分别处理 | 风险先分别计算可能性与后果，再合成 RF |
| 时差解释回活动延迟 | NPV 解释回采用的要求回报率，不能只显示正负号 |
| 用新条件重新画图和计算 | 项目筛选改变门槛或资源限制，检查排名是否仍适用 |
| 作图时能查看当前活动表 | 任何计算题都就近保留对应数字和单位 |

不需要让所有专题都出现九宫格、强制闯关或拖动节点。组织结构的判断依赖授权与管理关系，适合比较案例和修改组织图；把它改成没有语义的数字填空，会损害教学。

### D07　防止补充内容变成重复阅读

本项目曾在旧正文后增加案例卡。审查记录显示，74 个附加案例块中有 69 个紧接已有例子或表格，另有 12 页把应用题放在工作区之前。问题来自插入位置与内容重叠，不能靠再次加卡片解决。

准备增加一段内容时，先写明它补的是哪一个缺口：缺定义、缺条件、缺中间推理、缺操作，还是缺变化后的判断。如果只是重复同一个结论，应当合并或删除。如果缺的是顺序，就移动原段落。

建议的页面顺序是背景与概念、完整例子、概念辨析、计算或作图、应用判断。这个顺序可以随内容调整；关键是应用需要的知识和操作不能在应用之后才出现。

### D08　学习资料与制作资料分开呈现

医院建设是可沿用的情景。小组编号、作业要求、提交方式和分组身份不属于学习概念所必需的内容，应留在制作记录中。设计原则、版本差异和测试脚本也不应占据学习首页。

学习页可以有课程位置、术语与当前资料入口。制作经验包放在独立入口，供作者查阅。这样既能追溯出处，又不要求学习者重新阅读原文件或制作过程。


## 中文表达与术语

语言审阅要检查读者能否一次读懂关系。删掉几个常见套话，只能解决部分问题。更常见的障碍是人物和对象没有交代、名词堆在一起、代词指向不明，以及为了缩短句子删掉了必要的关系词。

### L01　先铺陈对象，再指出概念

用户给出的语言样板是：

> 项目中一项需要执行的具体工作。例如“给一个医院的服务台安装电脑，以及取号设备”，这是一项活动。活动名称要顾名思义，能让人知道具体做什么。

正式材料可以把术语补齐，保留这种展开方式：

> Activity（活动）是项目中一项需要执行的具体工作。例如，给一家医院的服务台安装电脑和取号设备，就是一项活动。活动名称应当让人知道具体做什么。

反例是“先认识医院里的这些工作”，随后直接列出代号。标题没有交代医院处于什么阶段，也没有说明为什么选这组工作。建议先说接待区准备开放，当前还需要哪些准备，再列活动。

短例子不必写成长篇故事。只要补齐对象和行动，读者就能理解定义。贯穿多页的例子才需要明确整体任务、完成目标和固定条件。

### L02　同一对象使用固定名称

| 已出现的问题 | 可采用的写法 | 为什么这样改 |
|---|---|---|
| “导视制作安装”与“制作并安装指路牌”交替出现 | 全文使用“制作并安装指路牌” | 避免读者猜测是否换了一项工作 |
| 一处写“设备”，另一处写“终端系统”，第三处写“服务设施” | 需要具体时写“电脑和取号设备” | 范围不同的名词不能随意替换 |
| 正文称“医院接待区”，题目突然称“业务场景” | 继续写“医院接待区” | 不为避免重复而改变指代 |
| 表格里只有 D，题目也只说 D | “D 制作并安装指路牌” | 编号用于定位，名称承担含义 |

名称过长时，优先调整列宽、换行或悬浮说明。只有在同一处先给过完整名称、简称不会歧义时，才使用简称。

### L03　英文、缩写与中文各自承担职责

首次出现时写正式英文名称、常用缩写和自然中文解释。例如：

> Total Float（TF，总时差）表示在不推迟规定项目完成时间的条件下，一项活动可以延迟的时间。

随后用具体活动说明它的作用，再给公式。不能写成“TF 是允许的时间浮动”，因为这只是把词换了一种说法。

同一个缩写在不同语境中可能有不同含义。FF 在时差中指 Free Float，在依赖关系中指 Finish-to-Finish；PV 在投资评价中指 Present Value，在挣值管理中指 Planned Value。标题、公式说明与速查应保留英文全称或当前语境，不能让读者依靠记忆猜测。

Slack／Float、Feeder Buffer／Feeding Buffer 等近义写法可以交代一次，再固定主要写法。不能为了统一中文而删除考试中需要识别的英文术语。

### L04　关系必须用完整句子解释

实际受到批评的写法：

> A先于B，B先于D；对D而言，B是紧前活动，A是更早的前置。

建议写法：

> 假设这段工作按 A→B→D 的顺序进行：负责人先确认指路牌的要求，设计师再完成图样，工人最后按图样制作并安装。对 D 这项工作来说，B 是紧前活动，因为工人要拿到图样才能开始制作。A 也是 D 的前置活动，它通过 B 间接影响 D。

原句给出了关系，却没有建立对象；修改后，读者能够从具体工作看出“直接”与“间接”的差别。若当前页没有活动表，就应在这段前面补上名称，或提供当前资料入口。

“完成到开始关系”也不能独自承担解释。可以写：

> Finish-to-Start（FS，完成-开始）表示前一项工作完成后，后一项工作才能开始。例如，设计师完成指路牌图样后，工人才能按图样制作指路牌。

有滞后量时，再补具体条件：“图样确认后还要等 1 天，工人才能开始制作。”不要把“FS＋1”当作新手已经理解的句子。

### L05　标题在正文之前就应当有用

| 反例 | 建议标题 | 标题应当说明什么 |
|---|---|---|
| 四列分别定义什么？ | 活动信息表的四列 | 当前正在读什么表 |
| 示范：从D这一行读回原来的意思 | 从活动表读出指路牌制作的开始条件 | 哪一项工作、要得到什么信息 |
| 先分清时点和时长 | 工期与开始、完成时间 | 接下来比较哪些量 |
| 用一个数把活动与工期分开 | 活动和工期的差别 | 需要理解的区别 |
| 含PB目标 | 加上项目缓冲后的计划完成时间 | 结果的含义 |

问句标题并非一律禁止。“电脑安装晚 1 天，医院接待区会晚开放吗？”有明确对象和问题，可以引出时差。无效的是必须读完正文才能知道所问对象的标题。

### L06　交代动作的主语，保留客观关系

反例：“数据告诉我们项目必须吃掉缓冲。”

建议写法：“设备安装晚了 2 天，原来预留的项目缓冲因此减少 2 天。”

这里需要说明的是延迟与缓冲变化，不需要让数据说话。“项目经理查看缓冲剩余时间，再决定是否调整安排”则交代了人的行动。

反例：“用一个数把活动与工期分开。”

建议写法：“活动说明要做什么，工期说明完成这项工作需要多久。”

不是所有无生命主语都要删除。“公式用于计算现值”“系统保存作答”“工期为 3 天”都能直接表达事实。需要避免的是“数据吃掉误差”“对话讲出结论”等使含义变得含混的拟人搭配。

### L07　把条件与结论放近

反例：“后续排程会受影响，但完工目标仍可保住。它超过了 FF，却没有超过 TF。”

建议写法：“这次延迟超过了 FF，因此后续活动的最早开始时间会改变；延迟仍在 TF 以内，项目可以按规定时间完成。”

如果当前重点是纠正“只要没超过 TF，后续就不受影响”的误解，可以进一步写：“即使延迟没有超过 TF，后续工作也可能推迟，因为延迟已经超过 FF。”

两种写法各有重点，不能把所有转折都机械替换成“因为”。需要保留真实因果和适用条件，避免只是为了显得有层次而连续使用“然而、但是、却”。

### L08　完整中文优先于压缩字数

| 反例 | 建议写法 |
|---|---|
| 零时点口径不额外加1 | 从时间 0 开始计时，从 2 到 5 经过 3 天，工期是 5−2，不再加 1。 |
| 按非关键汇入关键链的支路安排 | 在非关键支路接入关键链之前预留时间。 |
| 两种方案都覆盖关键路径 | 两种方案都使两条关键路径各缩短 1 天，项目因此可以提前 1 天完成。 |
| 更快释放资源 | 检查员完成这项工作后，就能开始检查下一项。 |
| 响应行动与授权 | 谁可以决定采取这项措施，谁负责执行。 |

这些修改保留了“的、并、后、之前”等关系词。名词串太长时，补回动作与对象通常比继续缩写更有效。

技术术语不必全部口语化。例如“风险应对”已有明确领域含义，定义后可以正常使用。不要为追求轻松口吻，把它改成随意的比喻。

### L09　删除说教和防御话术，保留必要条件

实际反例：“这一页要学会”“确认你理解了”。建议直接呈现问题、例子和操作：“根据活动表画出依赖关系”“核对这一步”。读者通过作答获得反馈，不需要不断接受学习命令。

实际反例是一段解释“这是教学情景，现实医院项目还会有更多接口和审批条件”的开场。它没有帮助读者计算或判断，反而把人从例子里拉出来。

必要假设仍需保留。例如：“本例从时间 0 开始，按天计算；先只考虑活动依赖，不限制人员数量。”这三项条件直接影响图和结果。将来进入资源约束时，再说明增加了什么条件。

判断一句话是否需要保留，可以问：删除它会不会改变读者对任务、输入、方法或结论的理解？如果不会，只是在提前为简化辩护，就应删除。

### L10　改句子之后重新读整段

本项目曾把短语替换为“按非关键汇入关键链的支路安排”，形成了新的病句。局部词语看起来更具体，整句关系却更难辨认。

语言检查按三个范围进行：先检查单句的主语与关系，再检查段内对象和因果，最后检查跨页名称与条件是否一致。全文搜词适合找候选问题，不能自动决定改法。

审阅时保留事实、单位和专业条件。把“第 4 个单元的用时”改成“前 4 个单元的平均用时”，即使中文更顺，也已经改变了学习曲线模型。

### 一次可复用的语言审阅

先只读标题、开头与新术语的首次定义，找悬空对象。接着读例子和题干，把每个代号指回完整名称。再读解析，检查是否真的解释原因，还是换一种说法宣布答案。最后通读整个专题，处理多余转折、同义词轮换和句子拼接。

审阅结果应写成“原句、障碍、改句、不能改变的事实”，而不是只写“已去除 AI 味”。


## 案例与练习

一个好例子要让读者知道为什么需要当前方法，并看见方法怎样作用于具体条件。给每页加上“医院”两个字，或在公式下面摆一组数字，都不等于建立了情景。

### Q01　给贯穿案例建立固定条件

本项目 5.1 的医院接待区案例可以作为设计稿的格式样板：

| 编号 | 活动名称 | 工期，天 | 直接紧前活动 |
|---|---|---:|---|
| A | 确认设备和指路牌的要求 | 2 | 无 |
| B | 设计指路牌 | 3 | A |
| C | 安装电脑和取号设备 | 6 | A |
| D | 制作并安装指路牌 | 2 | B |
| E | 检查设备和指路牌是否符合要求 | 1 | C、D |

当前只考虑表中依赖，按完成-开始关系安排，从时间 0 开始，工期以天计。C 与 D 都完成以后，E 才能开始。这些条件决定了关系图和计算，应该随例子保存，不能散落在页面之外。

案例记录还应包含整体任务、完成目标、单位、来源位置和允许变化的字段。表内活动名称与编号由同一份数据提供；正文、图节点、题目与悬浮资料使用它们。

不同方法可以继续使用医院背景，不必强迫它们使用完全相同的五项工作。切换到投资评价时，就重新交代投入、年度流入和发生时点。连续性来自明确的任务关系，不来自重复一个地名。

### Q02　完整例子要展开中间推理

反例：“E 的 ES＝8，EF＝9。”

建议写法：“E 要等电脑和取号设备安装完成，也要等指路牌制作安装完成。两项工作的最早完成时间分别是 8 和 7，因此检查最早在 8 开始。检查需要 1 天，最早在 9 完成。”

这个过程包含四件事：从活动表确定前置条件，从前一步结果取数，选择较晚的完成时间，再加上本项工期。公式 `ES=max(EF of predecessors)` 在这之后归纳，比一开始直接展示公式更容易对应到工作。

反向计算也需要解释为什么取最小值。若一项活动有两个后续工作，它必须同时满足两者的最迟开始要求。只满足较晚的那个，可能已经耽误另一个。因此完成上限由较早的那个决定。

### Q03　一个投资例子怎样分成讲解、练习和应用

讲解例子：院方现在投入 10 万元，第 1 年末和第 2 年末各收到 6 万元，贴现率为 10%。

| 步骤 | 计算 | 含义 |
|---|---|---|
| 记录现在的投入 | −10 万元 | 支出为负，发生在时间 0 |
| 第 1 年流入折算到现在 | 6÷1.1＝5.4545 万元 | 第 1 年只贴现一期 |
| 第 2 年流入折算到现在 | 6÷1.1²＝4.9587 万元 | 第 2 年贴现两期 |
| 合计净现值 | −10＋5.4545＋4.9587＝0.4132 万元 | 按 10% 的要求回报折算后，现值合计超过投入 |

分步练习可以换成第 1 年 4 万元、第 2 年 8 万元，让读者分别填写两笔现值与 NPV。输入单位仍为万元，初始投入和贴现率保持不变。这样练习同一方法，同时避免原样抄例题。

应用题再改变需要判断的事情。例如院方只允许采用回收期不超过 3 年的方案，甲在第 2 年回收后没有后续流入，乙在第 3 年回收、第 4 年还有流入。问题应区分“是否通过回收期门槛”与“能否据此判断整体价值”，而不再要求做一次同样的加法。

要检查假设是否前后一致。只有明确采用年内均匀流入，才可以插值得到分数年份；按年末收到整笔现金的题目，应报告首次回收的年末。

### Q04　同一知识点需要哪些题型

| 题型 | 检验对象 | 适合的例子 |
|---|---|---|
| 概念辨析 | 能否区分相近概念 | 活动与工期、风险与问题、成果与价值 |
| 读表与取数 | 能否找到对应输入 | 识别 D 的直接紧前活动；读取第 2 年现金流 |
| 计算或填写 | 能否完成方法步骤 | 正推、逆推、RF、NPV、学习曲线 |
| 作图与编辑 | 能否表达结构和约束 | AON、AOA、WBS、责任矩阵 |
| 查错 | 能否指出错误条件或步骤 | 贴现两期只除了一次；累计预算重复计入前期 |
| 条件变化 | 能否判断结论如何改变 | 延迟、资源减少、门槛改变、多关键路径 |
| 开放解释 | 能否根据证据提出判断 | 是否调整项目组合、如何处理新增需求 |

“题型不限”意味着要覆盖适合该知识点的用法，不意味着每个术语都机械生成七种题。一个分类概念未必需要画图；一个排程算法只给名词解释则明显不足。

### Q05　错误选项应对应真实误解

实际弱题曾用“会议次数”“合同页数”与患者等待时间比较。正确项几乎可以凭词面选出，无法判断读者是否理解成果与价值。

改写时，让错误项接近真实工作中会用到、但不足以支持结论的证据。例如比较等待时间是否改善，可以给出：同一统计规则下的等待时长并考虑患者数量变化；系统使用人数；设备安装数量与运行稳定性。后两者与项目相关，却不能直接证明等待变短。

编写每个干扰项时，写下一句“选择它的人可能把什么当成了什么”。若只能写“他没有认真看题”，干扰项通常需要重做。

建议示例：题干为“第 4 次配置用了 40 小时，学习率为 90%，怎样反推首次用时？”三个选项为 `40×0.9²`、`40÷0.9²`、`40÷4`。错误项分别对应顺推与逆推混淆、把单次时间当作四次总量。它们都能解释一个具体误解。

还要检查答案位置和长度。打乱位置可以减少位置规律，不能挽救只有正确项完整、专业而其他选项荒谬的题目。

### Q06　简单题之后安排有区别的变化

基于前面的活动表：

- D 的 TF 和 FF 都为 1 天。D 晚 0.5 天开始，E 仍可在时间 8 开始。
- B 的 TF 为 1 天，FF 为 0。B 晚 1 天开始，D 的最早开始从 5 变为 6，E 仍可在 8 开始，项目仍在 9 完成。
- B 晚 2 天开始，D 在 7 开始、9 完成，E 在 9 开始，项目在 10 完成。

这些变化分别检验后续工作的时间和项目结束时间，不是只问“有没有超过 TF”。读者需要解释哪个工作发生变化，以及变化怎样沿依赖传递。

更进一步，可以将 C 的工期从 6 天改为 5 天，形成两条同长关键路径。此时只缩短其中一条，未必能让项目提前。题目难度来自需要重新判断路径，数字不必更大。

### Q07　提示帮助下一步，解析说明原因

| 作答情况 | 不合适的反馈 | 建议反馈 |
|---|---|---|
| 没有填写 | 错误，请重试 | 填写这一项后再核对。 |
| E 的 ES 误填 7 | 答案是 8 | E 还要等电脑和取号设备安装完成。请比较两个紧前活动的完成时间。 |
| 第 2 年只贴现一次 | 公式用错了 | 这笔流入发生在第 2 年末，要折算两期，分母应包含 1.1²。 |
| RF 恰为 0.70 | 选错等级 | 本题高风险要求严格大于 0.70，边界 0.70 属于中风险。 |
| 开放题写满 | 已掌握 | 展示参考依据，让读者比较条件、证据和取舍。 |

提示与查看解法可以分开。提示指出应该检查的条件；解法可以显示正确值和完整推导。若提示已经直接给出正确值，学习记录也应按已获得答案支持处理。

当前工具已经区分“查看解法”与“独立完成”；更细的提示层级是后续制作可以采用的设计，不应写成所有旧页面都已实现。

### Q08　开放题提供评价依据

例如：“设备负责人提出更换型号，项目经理需要先做什么？”不能只用“同意”或“拒绝”判断。参考依据可以包括：核对批准要求，区分纠正缺陷与新增范围，检查成本和进度影响，确认审批权限，记录决定并更新受影响资料。

合理答案可能使用不同顺序或措辞。评分要围绕必要条件和理由，不应强迫读者复述参考段落。文本框填写了多少字，也不能作为掌握程度的证据。

### Q09　自动生成与 DIY 需要保留教学目的

生成活动表前，应明确练习要保留哪些结构。例如至少有一次汇合、存在可以并行的工作，以及用于比较 TF 和 FF 的活动。仅随机工期并不能保证这些条件。

生成后检查活动编号唯一、引用的紧前活动存在、工期合法、图无循环、所有时间计算一致。若练习声明每组都有某种结构，还需要检查该结构是否真的存在。

DIY 应允许用户修改名称、工期和依赖，同时指出具体问题：“A 的紧前活动 Q 不存在”，比“输入非法”更有用。修改关系后，应重新核对关系图和时间；不能让旧的全对标记继续有效。

### Q10　题库审阅不能只看题目数量

按“知识点、判断类型、误解、条件变化、反馈、答案记录”检查覆盖。两道数字不同却采用同一步计算的题，可以用于熟练操作，但不能据此声称已经覆盖解释、迁移与综合判断。

检查人员至少要读一次错误答案的反馈。有时题干与选项已经修改，解析仍在解释旧选项；这种题在自动判分时可以通过，实际教学却会制造矛盾。


## 交互、图表与学习记录

交互要让读者看见自己的操作如何改变结果。一个能输入参数的计算器，如果跳过了取数和推理，只能提供计算结果；一个可拖动的图，如果无法核对领域含义，也不能承担作图练习。

### I01　打开以后能决定下一步

专题页面先交代当前问题、必要术语和入口。选择知识主题与专题放在固定导航中；默认显示学习内容，练习与速查有清楚入口。学习记录导入导出、制作准则和审查报告可以折叠放置。

反例是默认显示大量模式、版本、随机参数和高级选项，要求初学者先决定使用方式。建议默认提供一组完整例子，让读者先完成必要操作；生成新题与 DIY 在他知道活动表是什么之后出现。

按钮写实际动作，例如“核对关系图”“查看这一步的解法”“生成另一组工期”。“继续探索”“确认掌握”不能准确说明点击后会发生什么。

### I02　当前条件始终在当前操作附近

用户认可正推逆推的分步填写，却发现页面底部看不到活动表。这说明操作区本身可以成立，所需背景仍然离得太远。

解决办法是提供“本页条件与术语”或“当前活动表”，在滚动到计算和图表区域后仍能打开。内容应该来自当前题目或工具状态：生成题显示生成的数据，DIY 显示自编名称与关系，改变参数后显示改变后的条件。

| 场合 | 就近资料应包含 | 不应该混入 |
|---|---|---|
| 原例子正推、逆推 | 当前活动名称、工期、紧前关系、时间约定 | 另一组生成题的数据 |
| 变式 NPV 分步计算 | 本题投入、各年流入、贴现率和单位 | 正文旧例子的现金流表 |
| 独立选择题 | 相关概念定义，题干中给出本题条件 | 暗示正确答案的原题完整解析 |
| AOA 事件时间 | 当前活动表与已核对的图 | 固定示范编号作为唯一标准 |

资料太长时，保留必要定义和表格，不把整节已讲过的正文塞进弹层。弹层的用途是减少回忆和翻查。

### I03　悬浮功能也要能用键盘和触屏

鼠标移到按钮上可以预览，键盘聚焦也能打开。点击后固定，便于移动指针、选取文字或滚动表格。Esc 关闭，关闭后不应把焦点丢到页面起点。

弹层位置应随视口调整，不能超出左右边界；内容较长时在弹层内部滚动。移动端使用点击，不能把鼠标悬浮当作唯一入口。按钮应说明内容是“活动表”还是“术语”，避免所有入口都叫“更多”。

检查时要真的完成“悬浮、移开、点击固定、移开、Esc、再次打开”这一串操作。只看一次截图，发现不了固定状态和关闭状态的问题。

### I04　AON 分成关系与时间两个阶段

第一阶段用节点表示活动、箭头表示依赖，让读者专心处理直接紧前关系。此时不需要同时展示一整套待填的开始、完成与时差字段。

关系正确以后，第二阶段在同一张图上显示九宫格时间。节点布局、活动名称和连线保留，读者不必重新建立图形记忆。按正推、逆推和时差逐步填写，当前阶段未涉及的字段可以淡化或暂时隐藏。

本项目节点布局采用：上排 ES、活动编号、EF；中排左格为 SL／TF，右侧两格合并显示活动名称；下排 LS、工期 DUR、LF。FF 在节点旁单列。不能为了凑成九格，将 TF 与 FF 放到同一格却不说明各自含义。

具体布局应核对课程图例，并在工具内提供字段说明。九宫格是表达方式，教学对象仍是活动与时间关系。

### I05　图形判分依据语义

| 图形 | 应检查 | 不应据此判错 |
|---|---|---|
| AON | 活动、直接依赖、循环、时间条件 | 节点拖到了另一位置，连线弯曲方式不同 |
| AOA | 活动依赖是否等价，事件条件，虚活动是否需要 | 事件编号与示范图不同但逻辑相同 |
| WBS | 批准范围是否完整覆盖、是否重复、分支含义 | 分支左右排列不同 |
| 责任矩阵 | 本题约定的执行和最终负责关系 | 合法使用 A/R 合并角色 |
| 利益相关者矩阵 | 横纵轴意义、等级、类型和行动依据 | 仅凭象限颜色不同 |

等价不意味着任何画法都正确。例如 AOA 删除虚活动后，若某项工作失去本来需要等待的前置条件，就改变了逻辑。反馈应该说清少了哪条等待关系。

合作—威胁矩阵在本课程中横向威胁左低右高、纵向合作上低下高，Mixed Blessing 位于右下。不能为了符合另一种常见图形习惯而旋转坐标，再保持原类型标签不变。

### I06　时间图的可读性也属于正确性

时间轴写单位和起点；条形起止位置对应实际数值；不同活动占用不同的行；基线、当前安排和缓冲用不同图例表示。标签写完整工作名称，过长时换行，不以截断后的半个词充当名称。

本项目曾检查到时间条的行间几何关系和 AOA 标签位置需要修正。数值计算正确时，重叠的条形仍会让读者误判活动能否并行。因此要分别核对数据、坐标换算和最终图形。

若支路倒排得到负的开始时间，而题目规定所有工作最早从 0 开始，应显示当前安排不可行及原因。不能把负数裁成 0，再继续显示原汇合时间，好像约束已经满足。

### I07　分步填写需要明确依赖

先显示当前步骤。空白不能当作 0，错误答案不能打开依赖它的后续步骤。正确后显示下一步，同时保留前面的条件与填写结果。

修改上游结果后，后续核对状态失效。例如第 1 年现值改变后，NPV 的旧正确标记不能保留。可以保留后续填写内容，方便读者修改；是否显示这些字段，由当前教学阶段决定。

普通阅读不必套用闯关模式。只有确实需要上一步结果才能继续核对的操作，才设置阶段依赖。不能因为概念选择题尚未作答，就阻止读者查阅一个已知公式。

### I08　记录“看过什么”和“做对什么”

| 发生的事 | 合适的状态处理 |
|---|---|
| 只打开页面或读完正文 | 不自动标记掌握 |
| 填写空白或错误值 | 保留作答，显示需要检查的条件 |
| 独立填写正确并核对 | 记录当前题目下的独立正确结果 |
| 先查看解法，再填写正确 | 标为对照解法完成 |
| 独立答对后再查看完整解析 | 保留已经取得的独立结果 |
| 改上游值、活动工期或关系 | 撤销受影响的后续核对 |
| 清空本组作答 | 清除该组作答和提示使用状态，保留其他组 |
| 开放解释题写完 | 保存文字，不自动判为理解正确 |

一次独立正确仍只是这道题上的表现，不能直接推广为已掌握整个专题。换条件后的题目和延后复习可以提供不同证据，但需要实际设计和执行。

本项目曾只在新分步题记录解法查看情况，普通填写题没有同步处理。规则需要落实到所有相关交互类型，而不是只在新做的那一种中生效。

### I09　版本变化与个人记录分别处理

题干、选项、正确答案或计算条件改变后，旧正确标记可能不再适用。每题保存内容指纹，恢复记录时比较当前版本。指纹不同则重新核对，尽量保留用户填写、图形位置和解释笔记。

旧记录没有指纹时，无法证明它对应当前题目。可以保留内容，同时撤销未能确认的核对结果。不要直接删除全部学习记录，也不要无条件接受旧的完成状态。

只修改不影响含义的排版时，不必强迫用户重做。需要判断的是语义是否变化，不能用整个页面文件的哈希代替每道题的身份。

### I10　保存、恢复和链接应当可预期

导入文件先完成格式和数据验证，再整体替换当前记录。文件损坏、版本不支持或字段非法时，现有作答应保持原样。读取期间可以显示“正在读取”，成功后再显示“已恢复”，不能提前宣布完成。

从专题链接进入时，链接负责首次定位；读者继续到下一节以后，刷新应恢复当前进度。若每次刷新都重新应用旧的 topic 参数，就会把读者送回专题首页。

浏览器本地存储按站点区分。电脑上的本地 HTML 与 GitHub Pages 地址不能自动共享记录。发布说明应明确提供导出 JSON、在线导入的路径。

### I11　窄屏检查要看到整页和局部

整页不能被一张宽表撑开。必要的图表可以在自己的区域横向滚动，操作按钮和正文仍保持可见。检查 390 像素宽度时，还要看姓名是否截断、悬浮资料能否展开、表格能否滚到最后一列。

页面没有横向溢出，只能证明一项布局条件。它不能证明字号合适、段落顺序合理，也不能代替实际用手指点击和输入。


## 审阅、同步与发布

审阅从最终页面开始。清单能帮助找遗漏，不能替代读者实际面对的正文、题目和图表。多次修改仍有同类问题时，应检查共同的制作方法，而不只是再做一次词语替换。

### V01　先定位最早的理解断点

从专题入口连续阅读，到第一次需要猜测对象、术语或条件的地方停下。记录当时已经提供了什么、还缺什么、读者被要求做什么。这样能区分“定义没有写”与“定义写在后面”，两者的修正方式不同。

反例：“页面读不懂，增加一个术语总表。”如果正文仍然提前使用陌生词，读者只是多了一个来回查表的任务。

建议：“紧前活动在第二页参与提问，完整活动表到第三页才出现。将活动名称和关系例子移到提问之前，并在题目旁保留当前表格。”修改对应的是已经定位的断点。

### V02　事实、阅读与行为分别审阅

| 审阅范围 | 主要问题 | 合适的证据 |
|---|---|---|
| 专业事实 | 定义、单位、公式、条件、阈值是否正确 | 原始材料、独立计算、原图核对 |
| 阅读过程 | 对象、术语和步骤是否按理解顺序出现 | 连续阅读、改前改后段落、任务走查 |
| 交互行为 | 输入后显示什么，修改后哪些状态失效 | 实际浏览器操作、保存恢复和异常输入测试 |
| 呈现 | 图表、表格、标签和弹层是否能读 | 桌面与手机截图、尺寸和位置检查 |
| 学习效果 | 读者是否能解释并处理变化后的题目 | 真实作答与观察，不能由前四项自动推定 |

一个检查失败，应回到它所属的层面处理。例如数值正确但条形重叠，要改绘图；操作正常但先问后教，要改顺序；所有技术检查通过，用户仍然不满意，应继续检查阅读和使用过程。

### V03　课件核对需要保留上下文

课程材料不是只用来核对英文拼写。公式旁的条件、原图坐标方向、表格权重、例题的现金流时点，都可能改变答案。

本项目中的核对重点包括：四重约束中的客户接受，Fully Loaded 费用概念，第 X 单元学习曲线与累计平均的区别，功能点权重，RF 的 0.70 边界，以及关键链中不同“50%”的含义。

图像型页面需要看实际图，提取出的文本未必包含箭头方向、象限位置和跨格关系。制作端保留课程位置与核对记录，学习端给出完整解释，不让读者重新翻课件才能理解。

若课程的术语用法与其他资料不同，先说明本课程采用的含义及适用条件。不要悄悄替换为另一套熟悉的分类，也不要把需要核对的差异写成已经确定的事实。

### V04　计算验证使用独立的预期结果

如果测试调用同一个计算函数生成“正确答案”，再检查页面是否等于这个答案，可能只是验证两处一起犯错。应保留少量手工或另一路计算得到的固定结果。

例如本例 AON 的总工期为 9 天，关键路径为 A-C-E，B 的 TF 为 1、FF 为 0。NPV 例子的金额为现在 −100000 元、两年末各 60000 元、贴现率 10%，净现值约 4132.23 元。这些数值可以独立核对页面。

测试也要覆盖会改变结论的边界：两个紧前活动谁更晚、多条关键路径、RF 恰等于阈值、支路倒排得到负时间、NPV 由正变负。没有新修改、失败或未解决疑点时，不必无限扩大同类测试。

### V05　把重复错误放进检查方法

适合自动检查的内容包括：术语或活动名称不一致，引用缺失，重复题目 ID，题干选项与反馈数量不匹配，旧占位符残留，当前资料显示错误案例，以及网页链接失效。

需要人工判断的内容包括：标题是否悬空，干扰项是否可信，例子是否有助于理解，转折是否多余，页面是否要求记住过多信息。

禁词扫描只能找到候选问题。“确认你理解了”出现在学习正文中可能需要删除，出现在设计经验的反例中则是必要内容。检查规则必须区分产物用途和引用语境。

给同类问题建立一条稳定规则和少量代表例子，比不断追加一份新清单更容易维护。

### V06　同一事实由同一处维护

| 内容 | 维护位置 | 派生产物 |
|---|---|---|
| 正式定义、公式、案例数据和题目 | 专题内容源 | 学习页、速查、题库和案例册 |
| 当前作答、图形与参数 | 学习状态 | 页面显示、导出记录、完成状态 |
| 设计规则与正反例 | 设计经验分章 | 网页阅读版、合订本、资料包 |
| 发布文件与部署结果 | 发布目录及部署记录 | 在线站点与交接信息 |

不同产物可以引用同一事实，但不能各自维护不同数字。学习页展开过程，速查保留定义和条件，案例册保存完整推导；共用来源不要求它们逐字复制同一篇长文。

生成器应当能重复执行，重复运行不再追加一遍内容。一次性修订脚本只用于历史修改，不能误当作正式构建流程反复执行。

### V07　测试自己的测试

本项目的一次记录恢复检查，在异步文件读取结束前就判断“已恢复”，产生失败。这属于测试没有等待实际完成状态，需要修正等待条件。另一处普通填写题缺少内容指纹，导入后记录结构发生变化，暴露了真实的数据一致性问题，需要修改实现。

处理失败时先复现并定位，不要为了让结果通过而直接放宽断言。也不要把每一个旧测试失败都解释成产品错误。页面结构改变后，旧选择器可能仍在寻找已经删除的重复案例层；应依据当前预期行为更新测试。

### V08　先形成可发布的具体产物

公开发布前，准备单独的发布目录，仅放当前站点需要的文件。检查入口文件、相对链接、资源大小、中文文件名、离线依赖和资料版本。原始课件、调试输出、测试记录和个人学习数据不应因为整目录上传而一并进入仓库。

本站实际发布采用静态 `index.html` 和配套 Markdown 文件，GitHub Pages 从 `main` 分支根目录部署。旧 PDF 尚未同步内容时，保留在本地旧产物中，不混入当前在线资料。

公开副本中的本机绝对路径没有使用价值，也可能暴露不必要的环境信息，应移除或改为正确的公开相对链接。学习功能仍使用同一份正式内容。

### V09　部署成功以后检查线上行为

“代码已推送”“构建成功”“网页返回 200”和“学习功能可用”是不同事实。最终检查应访问真实站点，确认当前内容版本，再尝试专题链接、计算输入、作图、速查、资料下载和刷新恢复。

本项目上线检查还比较了发布文件与线上文件的文本内容，避免只看到旧缓存页面。比较时处理 Git 对换行符的规范化，不能把 CRLF 与 LF 的差异误判为课程内容变化。

发布操作不应重建用户个人学习记录。迁移入口写清本地导出 JSON、在线导入即可，站点不需要上传或存储这些记录。

### V10　交接说明写结果和范围

反例：“全面升级，已达到最高教学品质，所有检查完美通过。”

建议：“主题 1 至 8 的当前内容已发布；已检查线上作图、计算、速查、下载和记录恢复。主题 9、10 仍在规划中，旧 PDF 未同步。”

设计经验交接还应指出规则放在哪里、如何修改并重新生成、哪几项属于新增建议。不能把“已经写进准则”当成“所有页面都已执行”。

### 连续返工时怎样换一种查法

写出前几次修改共同依赖的假设，例如“再加一张案例卡就能补足教学”。统计实际页面中哪里重复、哪里缺步骤、哪里先做题后见工具。根据分布决定是补内容、重排、合并还是删除。

本项目的重复案例层已经证明，增加解释数量并不自动改善阅读次序。下一轮审阅应检查改后的连续过程，而不继续以新增卡片数量作为完成证据。


## 返工案例

以下案例来自本次制作中的用户反馈、内容修订或检查记录。建议写法只代表修正方向，不表示已经通过学习者试验。每个案例保留问题发生的原因，避免把经验缩成“以后注意措辞”。

### R01　把复习索引当成教学工具

**实际问题：**内容以文件跳转和孤立知识块组织。用户指出，工具既不能服务复习，也不能服务学习与练习。

**造成的后果：**读者为了理解一个术语，需要离开当前页寻找定义、例子和表格。文件覆盖齐全，理解过程仍然缺失。

**设计修正：**把结构改为知识主题、专题、学习／练习／速查。课程对应关系保留为定位信息，理解所需正文留在工具内。

**可复用经验：**先检查读者要完成的动作，再决定产物结构。参见 D01、D03。资料列表适合检索原文件，不能代替教程。

### R02　用实现外形命名专题

**实际问题：**“九宫格 AON / Slack”先呈现陌生缩写和格子形式。用户追问为什么叫这个名字、初学者如何知道用途。

**造成的后果：**读者在理解任务之前，被迫先猜产品术语。即使后面提供完整图，也不知道为什么要填写。

**设计修正：**以“项目进度计划：从活动表到关键路径”说明任务，逐步引入正式英文术语、中文含义、用途和图例。

**可复用经验：**标题先说明对象和问题；界面形态放在操作说明中。参见 D03、L03、L05。

### R03　活动表晚于代号与问题出现

**实际问题：**用户在第二页遇到紧前活动和“D 等谁”等问题，直到第三页的活动信息表才理解字母代表什么。

**造成的后果：**读者以为自己没有记住前文，实际上所需信息还没有提供。后续练习变成回忆代号。

**设计修正：**先引入医院接待区的具体工作，定义活动和直接紧前关系，再读表、作图。题目写完整名称，操作旁保留活动表。

**可复用经验：**审阅最早一次使用的位置，不只检查“某处有没有定义”。参见 D02、L04、I02。

### R04　情景来源变化后，只替换名称不够

**实际过程：**情景曾采用医疗服务网站，用户后来核对为北部都会区发展策略中的医院项目，并进一步要求小组作业不要出现在学习资料中。

**可能延续的错误：**把“网站”替换成“医院”，却保留不相符的工作范围、活动和说明；或在每页反复交代情景来自小组任务。

**设计修正：**重新确定医院接待区的准备工作，给出具体活动；保留医院作为学习背景，移除分组身份和提交要求。

**可复用经验：**背景改动要检查任务边界与数据，不是只改一个名词。来源记录与学习正文分开。参见 D08、Q01。

### R05　中文润色只替换词语，产生新的病句

**实际问题：**“导视制作安装”“用一个数把活动与工期分开”等表达受到明确批评。一次替换还产生了“按非关键汇入关键链的支路安排”。

**造成的后果：**读者先要解析中文才能学习专业概念。同一工作换名称时，还会误以为增加了另一项工作。

**设计修正：**按完整句子交代谁做什么和条件关系；改成“制作并安装指路牌”“活动说明要做什么，工期说明需要多久”“在非关键支路接入关键链之前预留”。

**可复用经验：**单句修改后重读整段，再检查跨页名称。参见 L02、L06、L08、L10。

### R06　为了接近样板，不断叠加案例卡

**实际问题：**其他专题不如 5.1 时，曾通过追加术语总表、静态案例推导和变式题补强，原正文顺序仍被保留。

**检查记录：**74 个附加案例块，69 个紧接已有例子或表格，12 页的应用题位于工作区之前。这些数字描述旧页面的结构，不是学习效果统计。

**设计修正：**撤下重复层，将取数与推导补进原正文；计算和作图先于应用；完整扩展示例放入案例册和练习回看入口。

**可复用经验：**先检查失败的共同假设。复用样板中的推理过程，不照搬外观或增加一套平行内容。参见 D06、D07、V10。

### R07　弱干扰项换了长句，题目仍然弱

**实际问题：**部分题目以“全部删除”“超过一年自动成为运营”等选项作对照；用户指出题目太弱且不丰富。

**造成的后果：**读者无需理解知识，也能排除荒谬选项。把错误项写长，无法增加判断价值。

**设计修正：**改为真实但不足的证据、局部合理但不满足题目条件的处理方式，或常见计算混淆。保留分类、读表、计算、条件变化和解释的差异。

**可复用经验：**每个错误项都写出对应误解。题目数量只用于检查覆盖。参见 Q04、Q05、Q10。

### R08　一个例子内部使用两套条件

**实际问题：**资源切换案例一处说连续测试，另一处又安排交替；两种方案计算切换成本的方式也不一致。

**造成的后果：**读者无法判断差异来自排程方法，还是作者偷偷改变了条件。计算结果即使分别能算出来，比较也失去依据。

**设计修正：**明确每个项目有两项可以分开的独立测试，每项 1 天；每次切换都用 0.5 天。成组执行为 4.5 天，交替执行为 5.5 天。

**可复用经验：**比较方案先统一条件，再解释结果差异。参见 Q01、V03、V04。

### R09　公式正确，概念顺序仍然倒置

**实际问题：**现金流、回收期和贴现回收期混在一起，贴现尚未介绍就进入贴现回收。工具能输出结果，读者仍不知道数字怎样得到。

**设计修正：**拆开现金流和累计，先讲普通回收，再引入现值、贴现率和 NPV，最后讲贴现回收与 IRR。增加逐年现值填写，应用题改为比较指标能回答的问题。

**可复用经验：**计算正确只满足事实条件。先修概念和中间转换必须另查。参见 D02、Q02、Q03。

### R10　悬浮资料存在，但不是当前题的数据

**实际风险：**将整篇原案例塞进统一悬浮框，虽然减少了翻页，却可能让变式计算引用原案例的金额或工期。

**实际处理：**学习页资料从当前正文定义和表格生成；变式分步题使用自己的题干条件；生成题与 DIY 的活动表跟随当前数据。

**可复用经验：**“附近有表格”还不够，要检查表格属于哪个题目、版本和参数状态。参见 I02、I03。

### R11　“完成”状态比实际作答更乐观

**实际问题：**新分步题已区分查看解法，普通填写题尚未同步；普通题还缺少初始化时的内容指纹。旧状态和新题可能不一致。

**实际处理：**统一记录查看解法情况，独立答对后再看解析保留原结果；题目指纹变化撤销核对，保留填写内容；补查导入、刷新和重做时的状态。

**可复用经验：**状态规则要覆盖所有相关题型。新组件正确，不代表旧组件已经继承规则。参见 I08、I09、V07。

### R12　旧链接不断覆盖恢复位置

**实际问题：**带 `topic` 的入口链接可以定位专题，但刷新时重复应用，会把已经继续学习的读者带回最初页面。

**实际处理：**首次进入时消费定位参数，之后按保存的位置恢复。检查深链接、继续学习、刷新这一完整过程。

**可复用经验：**入口意图和持续状态要分开。参见 I10。

### R13　静态文件发布后，记录和资料仍要重新核对

**实际过程：**站点发布到 GitHub Pages。公开目录保留当前 HTML 与 Markdown，移除无效本机链接；旧 PDF 没有进入当前在线资料。

**实际检查：**线上文件版本、专题链接、NPV 参数修改、AON 作图、速查、下载、刷新和移动布局。另说明本地文件与在线站点之间需要导出和导入学习记录。

**可复用经验：**推送成功不能代替线上访问；同一台电脑也不代表两个地址共享存储。参见 V08、V09、I10。

### R14　功能检查通过后，用户仍然不满意

**实际反馈：**在多轮修改与检查后，用户仍明确表示“我并没有满意”。

**不能据此做的事：**重复罗列页数、题数和通过的测试，或将新的完成清单当作回应。

**应当做的事：**回到最终阅读过程，检查顺序、重复、条件、例子与选择题的判断价值。分别记录技术检查结果和人工阅读判断，等待实际使用反馈，不替用户宣布满意。

**可复用经验：**检验证据不能跨层使用。参见 V01、V02、V10。


## 制作模板与验收表

这些模板供作者在制作和审阅时使用，不需要全部显示给学习者。已有材料能回答的字段直接引用原记录，不再维护第二份相同内容。

### T01　专题设计稿

```text
专题名称：
读者正在解决的问题：谁需要完成什么，为什么现在需要这个方法？
完成后的可观察动作：读表、判断、计算、作图或解释什么？
先修概念：哪些要在当前内容之前出现？
正式术语：英文、缩写、中文含义、课程位置。
贯穿案例：对象、任务、完成条件、固定名称。
数据与假设：单位、时点、数量、依赖、限制。
阅读顺序：每一步使用什么输入，得到什么结果？
练习安排：基础辨析、分步操作、独立变化、解释。
当前资料：在作答或操作位置需要保留哪些表格和定义？
速查：定义、公式、条件、单位、例子与易混点。
验收证据：专业核对、连续阅读、交互操作分别怎样检查？
```

填写“阅读顺序”时，不只写页面名称。写清前一步产生的结果为何成为后一步的输入，才能检查是否缺了转换。

### T02　填好的设计稿示例

| 字段 | NPV 专题的建议填写 |
|---|---|
| 当前问题 | 院方比较现在的投入与以后收到的款项，金额发生时点不同 |
| 读者动作 | 从现金流表取数，将各期金额折算到现在，求和并解释正负号 |
| 先修概念 | 现金流符号、时间 0、年末时点、普通累计 |
| 正式术语 | Present Value、Discount Rate、Net Present Value |
| 贯穿条件 | 现在投入 10 万元，两年末各流入 6 万元，贴现率 10% |
| 阅读过程 | 定义现值，说明贴现率，分别折算两笔流入，扣除现在的投入，再解释结果 |
| 分步练习 | 改为第 1 年 4 万元、第 2 年 8 万元，依次填写现值和 NPV |
| 应用 | 改变要求回报率，解释同一现金流的 NPV 为什么改变 |
| 就近资料 | 当前题目的现金流时点、金额、单位与贴现率 |
| 独立核对 | 原例 NPV 约 0.4132 万元；分步题 NPV 约 0.2479 万元 |

### T03　概念与术语卡

```text
正式英文及缩写：
中文名称：
定义：用完整句子说明它是什么。
为何需要：它帮助处理哪个具体问题？
具体例子：对象、行动和结果。
相近概念：只列当前确实需要辨析的概念。
首次出现位置：在它参与题目或公式之前。
必要条件：定义或方法在哪些假设下使用？
```

写完定义后，暂时遮住例子。如果定义只剩“某种机制”“相关过程”“用于优化”等模糊词，就需要重写。例子负责使概念具体，不能替代概念本身。

### T04　题目设计卡

```text
要检验的判断：
题干：包含完整对象、条件与单位。
正确答案及推理：
错误选项一：
对应误解：
错误选项二：
对应误解：
读者从哪里获得所需知识：
首次错误时的提示：指出要检查的条件，是否直接给出结果？
查看解法时显示：
变式如何改变需要判断的条件：
何时撤销旧核对：
```

审阅者可以先不看正确答案，尝试说明每个选项为什么可能被选。如果两个错误项只能解释为“明显不合理”，应重新编写。

### T05　语言问题卡

```text
原句或原段：
当时已经给出的背景：
阅读障碍：指代、顺序、名称、句法、条件或无用话术。
改写：
必须保留的专业事实：
跨页检查：相关名称、表格、题干和解析是否一起更新？
```

填好示例：原句是“用一个数把活动与工期分开”。障碍是行动与目标不清。改成“活动说明要做什么，工期说明完成这项工作需要多久”。保留的事实是两者分别表示工作与持续时间。再检查题目是否仍在把开始时点称作工期。

### T06　交互状态检查表

| 操作 | 应看到的变化 | 必须保留的内容 |
|---|---|---|
| 首次进入题目 | 当前条件与第一步 | 可查术语和单位 |
| 不填就核对 | 提示填写，不判为零 | 其他已填字段 |
| 填错后核对 | 指出需要检查的条件 | 原作答 |
| 独立答对 | 记录对应结果，继续依赖步骤 | 前面的输入和解释 |
| 先看解法再答对 | 标为对照完成 | 查看解法的记录 |
| 改前一步 | 后续核对失效 | 可继续修改的填写内容 |
| 改题目条件 | 当前题重新核对 | 其他题目和个人笔记 |
| 导入损坏文件 | 显示原因，不替换记录 | 当前全部作答 |
| 由链接进入后继续并刷新 | 恢复实际当前位置 | 参数和作答 |

### T07　连续阅读走查

每次选一个完整专题，从入口开始，暂时不打开源码和完成清单。

1. 只看标题和开头，写出当前对象、任务与问题。写不出来就记录断点。
2. 标出第一次出现的英文词、缩写与代号，检查是否已解释。
3. 顺着例子核对数据，检查中途是否换了条件或名称。
4. 完成一次错误作答，检查反馈是否指向误解。
5. 完成分步操作，在页面底部查找所需表格。
6. 修改一个会影响结果的条件，检查图、数值、解释与状态是否同步。
7. 只看速查，检查能否知道公式中的量和使用条件。

记录具体位置、原句、截图或操作结果。“读起来不顺”可以作为起点，但还需要定位到可修改的内容。

### T08　逐专题验收表

| 检查项 | 合格时能够给出的证据 | 结果与位置 |
|---|---|---|
| 概念顺序 | 首次使用前已有可理解的定义 | 待填写 |
| 背景与对象 | 读者无需猜测当前在做什么 | 待填写 |

| 就近资料 | 当前题和参数对应的条件可查 | 待填写 |
| 图形语义 | 轴、单位、连线和时间位置正确 | 待填写 |
| 状态与记录 | 查看解法、修改、刷新、导入行为符合规则 | 待填写 |

不把各项换成总分后互相抵消。例如术语顺序错误，不能靠题目多或颜色好看补分。尚未检查的项目明确保留“待填写”，不预先标为通过。

### 专业核对中的典型问题

| 范围 | 应保留的经验 |
|---|---|
| 项目基础 | 成果、价值和成功维度分别说明；课程四重约束中的客户接受不能漏掉 |
| 战略与筛选 | 战略对应、门槛、评分与组合约束分开；全局权重由各层相乘 |
| 投资评价 | 先解释现金流与时点；普通回收和贴现回收分开；NPV 与 IRR 的问题不同 |
| 利益相关者 | 保留原图轴向与类型；沟通行动对应需求与权限，不能只凭角色名称判断 |
| 组织与冲突 | 结构分类要看授权和报告关系；行动方案不能用明显荒谬选项凑数 |
| 范围与 WBS | 包含关系不等于执行先后；工作包与词典先于范围基线的组合解释 |
| AON 与依赖 | 先关系后时间；FS、SS、FF、SF 的开始和完成约束分别展开 |
| 甘特图与 AOA | 预测日期与实际日期分开；AOA 按依赖等价核对，不能只比编号 |
| 成本与预算 | 工时、工期、单位费用和累计值不混用；课程表格权重逐项核对 |
| 赶工 | 每轮重新找关键路径，多条关键路径要同时满足；单位压缩成本不能单独决定方案 |
| 风险 | 风险与已发生的问题分开；RF 等级阈值按课程定义；等级分数不直接当作概率金额计算 |
| 资源与关键链 | 比较方案使用同一资源与切换条件；50% 完成概率、50% 链长规则和平方和开方分开 |

### 什么时候使用哪个技能

| 技能 | 本类任务中的使用要求 | 应产生的结果 |
|---|---|---|
| `humanizer-chinese` | 中文初稿或改写后使用；按文件或嵌入模式审阅 | 修正句意、翻译腔、同义词轮换和无必要转折，交付终稿 |
| `unslop` | 所有说明文字交付前使用 | 删除模板话术、无信息修辞和装饰性总结 |
| `product-taste-gates` | 审阅页面、图表、默认展示和报告时使用 | 当前任务所需事实可见，诊断与制作内容归入独立入口 |
| `fact-closure-collaboration` | 整理反复反馈、经验和交接时使用 | 要求、事实来源、修改和验证可以对应，不制造平行规则 |
| `technical-writing` | 术语、指代、条件或句法不清时补充使用 | 同一名称表示同一对象，相关词靠近，条件紧邻结论 |
| `principle-attack-the-premise` | 两次以上修改依赖相同假设且仍失败时使用 | 先记录共同假设和实际分布，再决定是否改变方法 |

每次使用技能，都应读当前安装版本的 `SKILL.md`，再按本项目需求取用。技能名称不等于检查已经发生，更不能成为“语言一定自然”的保证。

本项目对通用写作建议有明确取舍：必要表格可以留在学习操作旁；目标不必做成反复说教的栏目；自然中文不受机械句长限制；技术假设必须保留，防御话术不进入学习正文。用户的这些具体要求优先。

### 后续怎样补充经验

出现新问题时，先定位到现有规则。若只是新的例子，加入对应章节；若确实揭示了新条件，补充规则的适用范围，再给一个能区分新旧做法的例子。

记录验证时使用“实际检查了什么、得到什么结果”。没有真实学习者观察，就不要写提升比例或掌握率。用户的新反馈可以改变此前的设计判断，旧规则需要随之合并或改写，而不是永远保留互相矛盾的两条要求。

### 当前项目的维护入口

分章原稿位于 `work/design_experience`。修改原稿后运行 `python -X utf8 work/build_design_experience.py`，会重新生成阅读版、合订本与独立压缩包。网页样式和搜索逻辑分别在同目录的 `reader.css`、`reader.js` 中。

资料包中的 Markdown 可以在其他项目中独立编辑和使用。HTML 是生成时的快照，编辑 Markdown 后不会自动变化；需要同步网页时，在制作工作区重新构建，或用其他 Markdown 工具重新排版。

更新在线站点时，先运行发布准备脚本 `work/prepare_github_pages.py`，检查发布目录里的差异，再提交和推送。完整复习包由 `work/package_outputs.py` 生成。不要把这个流程与历史上的一次性替换脚本混用。
